지난 포스팅에서 Nginx를 설치하고, Reverse Proxy로 동작할 수 있도록 최소한의 구성을 적용해봤습니다. 

클라이언트가 Reverse Proxy(nginx-rp)에 80포트로 요청을 보내면 애플리케이션 서버로 전달될 수 있습니다. 하지만, 8001 포트로 애플리케이션 서버(api-01)에 직접 요청을 보내는 것도 가능합니다.

현재 구조는 다음과 같습니다.

```nohighlight
┌─────────────────────────┐
│       Windows 11        │
│       (Client)          │
└───────┬─────────┬───────┘
        │         │
        │         │
        ▼         ▼
     Port 80   Port 8001
        │         │
        │         │
┌───────┴─────────┴───────┐
│   Oracle VM (Ubuntu)    │
│   IP : 192.168.56.11    │
│                         │
│ ┌───────────────────┐   │
│ │ nginx-rp          │   │
│ │ Port : 80         │   │
│ └───────────────────┘   │
│                         │
│ ┌───────────────────┐   │
│ │ api-01            │   │
│ │ Port : 8000       │   │
│ └───────────────────┘   │
└─────────────────────────┘
```

* Client → nginx-rp (80 포트)
* Client → api-01   (8001 포트)

즉, 여전히 애플리케이션 서버는 외부에 노출되어 있는 상태입니다.

애플리케이션 서버는 Reverse Proxy를 통해서만 접근할 수 있어야 하기 때문입니다.

현재 상태는 Reverse Proxy가 구성되었지만 애플리케이션 서버 보호라는 목적을 완전히 달성했다고 보기 어렵습니다.

---

## 1. Docker Network 생성

지금부터는 애플리케이션 서버에 대한 직접 접근을 차단하고, Reverse Proxy를 통해서만 접근할 수 있도록 구성을 변경해야 합니다.

이를 위해 먼저 Reverse Proxy와 애플리케이션 서버가 Docker의 내부에서 통신할 수 있도록 Docker Network를 생성할 필요가 있습니다.

다음의 명령어를 실행해서 rp-network라는 이름을 가진 Docker Network를 생성할 수 있습니다.

```bash
$ docker network create rp-network
```
동일한 네트워크에 연결된 컨테이너들은 Docker Network를 통해 서로 통신할 수 있습니다.

컨테이너 이름을 이용해서 다른 컨테이너에 접근할 수 있기 때문에 별도의 포트 노출 없이도 서비스 간 통신이 가능합니다.

Docker Network는 다음의 명령어를 실행해서 조회할 수 있습니다.

```bash
$ docker network ls
```

위 명령어 실행에 대한 응답으로 반환되는 Docker Network 목록에 다음과 같이 rp-network가 포함되어 있어야 합니다.

```nohighlight
NETWORK ID     NAME         DRIVER    SCOPE
4347c31fdfbe   bridge       bridge    local
278e34f32899   host         host      local
1efc34a92de3   none         null      local
65dbef218e5a   rp-network   bridge    local
```

## 2. 애플리케이션 서버 재구성

Docker Network를 생성되어도 애플리케이션 서버가 자동으로 내부 네트워크를 사용하는 것은 아닙니다.

컨터이너 실행 상태를 확인해보면 현재 애플리케이션 서버는 여전히 8001 포트를 외부에 노출한 상태로 실행되고 있습니다.

```bash
$ docker ps
CONTAINER ID   IMAGE        COMMAND                  PORTS
85b2de399fc1   simple-api   "java -jar simple-ap…"   0.0.0.0:8001->8000/tcp
```

따라서 먼저 기존 애플리케이션 서버 컨테이너를 제거해야 합니다.

```bash
$ docker rm -f api-01
```

그리고 앞에서 생성한 rp-network에 연결되도록 애플리케이션 서버를 다시 실행했습니다.

```bash
$ docker run -d \
  --name api-01 \
  --network rp-network \
  -e SERVER_NAME=api-01 \
  simple-api
```

기존 실행 명령어와 비교하면 -p 8001:8000 옵션이 제거된 것을 확인할 수 있습니다.

이제 애플리케이션 서버는 더 이상 가상머신 외부에 포트를 노출하지 않습니다.

대신 동일한 Docker Network에 연결된 컨테이너만 접근할 수 있는 상태가 되었습니다.

변경된 구조는 다음과 같습니다.

```nohighlight
┌─────────────────────────┐
│       Windows 11        │
│       (Client)          │
└──────────┬──────────────┘
           │
           ▼
        Port 80
           │
┌─────────────────────────┐
│   Oracle VM (Ubuntu)    │
│                         │
│ ┌───────────────────┐   │
│ │ nginx-rp          │   │
│ │ Port : 80         │   │
│ └─────────┬─────────┘   │
│           │             │
│      rp-network         │
│           │             │
│           ▼             │
│ ┌───────────────────┐   │
│ │ api-01            │   │
│ │ Port : 8001       │   │
│ └───────────────────┘   │
└─────────────────────────┘
```

* Client → nginx (80) → api-01 (내부)

애플리케이션 서버에 대한 외부 포트 노출은 제거되었지만 아직 Nginx는 기존 설정대로 192.168.56.11:8001로 요청을 전달하도록 구성되어 있습니다.

따라서 다음 단계에서는 Nginx가 Docker Network 내부의 애플리케이션 서버로 요청을 전달할 수 있도록 설정을 변경해보겠습니다.
