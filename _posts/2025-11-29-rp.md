이번주 회사에서 운영되고 있는 서비스의 인프라 구성을 변경하는 작업을 수행했습니다. 

DMZ에 배치되어 있던 API 게이트웨이를 TrustZone으로 이전하는 것이 핵심 내용으로 장기간 누적되어 있던 기술부채를 청산하는 의미도 있었습니다. 

<img class="main-image" src="/assets/images/network.png" alt="네트워크 이미지">

---

## 1. 작업 필요성

서비스의 운영 관점에서 다음과 같은 문제가 있었습니다.

**보안 설정 관리의 복잡성 증가** 

* DMZ에서 운영되고 있는 API 게이트웨이의 보안 정책을 개별적으로 적용하고 관리 

* 작업자의 실수로 보안 정책 적용이 누락되거나 불일치하는 상황이 발생할 가능성 존재 

* 보안 정책 변경에 많은 시간이 소요 

**공격 표면 증가**

* 외부와 접점이 있는 DMZ에서 API 게이트웨이가 운영 

---

## 2. 작업 목표

작업 목표는 다음과 같았습니다.

> "API 게이트웨이를 안전한 TrustZone으로 이동시켜 보안을 강화하고, 관리 효율성의 향상을 기대"

---

## 3. 인프라 구성

### 3.1. 작업 전

```nohighlight
+-----------------------+
|    Client(Internet)   |          
+-----------------------+
            |
            v
+-----------------------+
|      API Gateway      |          
|         (DMZ)         |
+-----------------------+
            |
            v
+-----------------------+
|      API Server       |          
|      (TrustZone)      |
+-----------------------+

```
---

### 3.2. 작업 후

```nohighlight

|     Client(Internet)  |         
+-----------------------+
            |
            v
+-----------------------+
|      RP Server        |          <-- 요청 라우팅 및 보안 강화
|        (DMZ)          |
+-----------------------+
            |
            v
+-----------------------+
|      API Gateway      |          <-- 보안 강화 및 관리 일원화
|      (TrustZone)      |
+-----------------------+
            |
            v
+-----------------------+
|      API Server       |          
|      (TrustZone)      |
+-----------------------+

```

---

## 4. 기대효과

* **보안성 강화**: DMZ 역할을 최소 기능으로 단순화 → 공격 표면 축소  

* **운영 효율성 증가**: TrustZone 내에서 일괄적으로 보안 정책 배포 → 작업 시간 단축
