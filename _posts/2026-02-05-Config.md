## 스프링 애플리케이션에서 설정의 출발

스프링 애플리케이션에서 설정을 다룰 때, 그 출발점은 설정 정보를 정의하는 `application.properties` 또는 `application.yaml` 파일입니다.

**application.properties 예시**
```bash
feature.logging.enabled=true
external.api.timeout=3000
```

**application.yaml 예시**
```bash
feature:
  logging:
    enabled: true

external:
  api:
    timeout: 3000
```

두 파일은 표현 방식만 다를 뿐, 스프링 입장에서는 동일한 설정 정보를 가지고 있습니다. 프로젝트의 특성이나 팀의 선호에 따라서 선택해서 사용하면 됩니다. 개인적으로는 설정의 개수가 늘어나고, 복잡한 계층 구조를 가지는 설정을 표현하는 경우에는
`application.yaml`을 사용하는 것이 조금 더 읽기 쉽다고 느껴졌습니다.

## 스프링에서 설정을 다루는 가장 간단한 방법, @Value

`@Value` 어노테이션을 사용하면 설정 키를 바로 변수에 매핑할 수 있기 때문에 매우 직관적이고, 간편하게 설정 정보를 처리할 수 있습니다. 

사용 방법은 다음과 같습니다. 
> @Value(${키:기본값})

`application.properties` 또는 `application.yaml`에서 external.api.timeout 속성에 할당된 값을 가져와서 사용하려면 아래처럼 코드를 작성하면 됩니다. 해당 속성이 존재하지 않거나 값이 할당되어 있지 않다면, 기본값으로 지정된 3000이 사용될 것입니다.
    
```java
@Value("${external.api.timeout:3000}")
private int timeout;
```

## @Value의 한계

하지만, 설정의 개수가 늘어나면서 계층 구조가 복잡해지면 @Value 어노테이션은 한계가 드러나기 시작합니다.

어떤 애플리케이션에서 API의 동작을 설정하기 위해서 url,timeout,retry라는 3개의 속성이 필요하다고 가정해보겠습니다. 

이들 속성을 하나의 단위 기능으로 묶어
`application.yaml`을 다음과 같이 작성할 수 있습니다.

**application.yaml**
```bash
api:
    url: https://example.com
    timeout: 3000
    retry: 3
```

API라는 단위 기능을 구성하는 설정 구조가 비교적 명확합니다.

1️⃣ 설정 코드의 분산

그리고 @Value 어노테이션으로 `application.yaml`에서 읽어온 속성의 값으로 애플리케이션의 동작을 설정하는 코드를 아래처럼 작성할 수 있을 것입니다.

```java
@Component
public class ExternalApiClient {

    @Value("${api.url}")
    private String apiUrl;

    @Value("${api.timeout:3000}")
    private int timeout;
}

@Component
public class ExternalApiRetryPolicy {

    @Value("${api.retry:3}")
    private int retryCount;
}
```

**이상한 점이 보이나요?** 

분명 동일한 단위 기능(API)을 구성하는 설정이지만,
`ExternalApiClient`와 `ExternalApiRetryPolicy` 클래스에 나누어 구현되어 있습니다.

이렇게 되면
애플리케이션의 동작 방식을 결정하는 설정 구조가
코드 상에서 한눈에 드러나지 않게 되고,
설정을 이해하기 위해 여러 클래스의 코드를
함께 살펴봐야 하는 상황이 발생하게 됩니다.

문제는 설정이 흩어져 있다는 점 자체보다,
**설정의 구조와 의도가 코드에 자연스럽게 드러나지 않는다**는 점입니다.

## 설정을 객체로 묶어 표현하는 방법, @ConfigurationProperties

지금까지 살펴본 것처럼, 설정의 개수가 늘어나고 계층 구조를 가지기 시작하면 @Value 어노테이션만으로는 설정의 구조와 의도를 코드에 명확하게 드러내기 어렵게 됩니다.

이러한 문제의 해결책으로 스프링은 설정을 객체 단위로 묶어서 바인딩할 수 있는 방법을 제공합니다. 이때 사용하는 어노테이션이 바로 @ConfigurationProperties입니다.
