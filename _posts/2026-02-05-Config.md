## 애플리케이션 설정

애플리케이션의 동작을 규정하는 값을 외부에서 정의하고, 이를 실행 시점에 주입하는 과정을 **설정**이라고 합니다. 즉, 설정은 애플리케이션이 **어떻게 동작해야 하는지를 결정하는 기준**이라고 볼 수도 있습니다.

**예시) 애플리케이션 설정으로 주입되는 값**

1. 외부 연동
    * API URL
    * 타임아웃 값
    * 연결 재시도 횟수
2. 기능 동작
    * 특정 기능의 활성화 여부
    * 기능별 동작 옵션
3. 환경 정보
    * 개발/스테이징/운영 환경별 구동 정보
    * 로그 레벨
    * 임계값(threshold)

이러한 값들은 코드 내부에서 직접 정의하기보다는 외부에서 정의했다가 애플리케이션 실행시점에 설정으로 주입하는 것이 일반적입니다. 환경이나 정책의 변화에 코드의 변경없이 유연하게 대응하기 위함입니다.

## 스프링 기반 애플리케이션 설정의 출발점

스프링 기반 애플리케이션은 `application.properties` 또는 `application.yaml` 파일이 설정의 출발점입니다. 이 파일들에 애플리케이션이 어떻게 동작해야 하는지를 결정할 값들이 정의되기 때문입니다.

**예시) application.properties**
```bash
feature.logging.enabled=true
external.api.timeout=3000
```

**예시) application.yaml**
```yaml
feature:
  logging:
    enabled: true

external:
  api:
    timeout: 3000
```

두 파일은 표현 방식만 조금 다를 뿐, 동일한 설정 정보를 정의하고 있습니다. 프로젝트의 특성이나 팀의 선호에 따라서 선택해서 사용하면 됩니다. 개인적으로는 계층 구조가 드러나는 `application.yaml` 파일을 사용하는 것이 가독성이 조금은 더 좋게 느껴져서 선호하는 편입니다.

## 설정 값을 코드에 주입하는 가장 간단한 방법, @Value 어노테이션

설정 값을 코드에 주입하는 가장 간단한 방법은 `@Value` 어노테이션을 사용하는 것입니다. `@Value` 어노테이션은 `application.properties` 또는 `application.yaml` 파일에 정의된 키와 코드 내부에 정의된 변수를 직접 연결해 주기 때문에 매우 직관적입니다.

사용 방법은 다음과 같습니다. 
> @Value(${키:기본값})

설정 정보에 정의된 `external.api.timeout` 값을 코드 내부의 `timeout` 변수에 주입하고 싶다면 아래와 같이 작성하면 됩니다.

```java
@Value("${external.api.timeout:5000}")
private int timeout;
```

timeout 변수에는 external.api.timeout이 가지고 있는 값인 3000이 주입됩니다. 만약, 설정 정보에서 값을 찾을 수 없으면 기본값으로 선언된 5000이 주입됩니다.
    
## @Value 어노테이션의 한계

애플리케이션의 규모가 커지면 설정의 개수도 많아지고, 계층 구조도 복잡해질 수 밖에 없습니다. 이때 `@Value`를 사용하면 **설정 값의 주입 자체는 쉽지만, 이후 관리가 어려워질 수 있습니다.** 

API로 외부 시스템과 연동하기 위해 url,timeout,retry를 설정해야 하는 상황을 가정해보도록 하겠습니다. 우선, 애플리케이션에서 설정 정보를 가져올 수 있도록 `application.yaml` 파일을 아래처럼 작성할 수 있을 것입니다.

**application.yaml**
```yaml
external:
    api:
        url: https://example.com
        timeout: 3000
        retry: 3
```

`@Value` 어노테이션을 사용하면, 아래 코드처럼 설정 값을 하나씩 개별적으로 주입해야 합니다. 

```java
@Component
public class ExternalApiClient {

    @Value("${external.api.url}")
    private String url;

    @Value("${external.api.timeout:3000}")
    private int timeout;

    @Value("${external.api.retry:3}")
    private int retry;
}
```

만약 설정 값의 개수가 100개 이상이라면 어떻게 될까요? 수많은 `@Value` 어노테이션으로 코드의 가독성은 떨어지고, 단위 기능의 설정 구조가 어떻게 구성되어 있는지 직관적으로 이해하기 어렵게 될 것입니다.

또한, 아래 코드처럼 동일한 설정 값을 주입하는 코드가 여러 클래스에서 중복 사용될 수도 있습니다. 

```java
@Component
public class ExternalApiWebClient {

    @Value("${external.api.url}")
    private String url;

    @Value("${external.api.timeout:3000}")
    private int timeout;

    @Value("${external.api.retry:3}")
    private int retryCount;
}

@Component
public class ExternalApiBatchClient {

    @Value("${external.api.url}")
    private String url;

    @Value("${external.api.timeout:3000}")
    private int timeout;

    @Value("${external.api.retry:3}")
    private int retryCount;
}

```

이런 경우 `application.properties` 또는 `application.yaml` 파일에서 설정 키가 변경되면, 해당 키로 설정을 주입하는 모든 클래스의 코드를 찾아서 일일이 수정해야 합니다. 

## 설정을 객체로 묶어 표현하는 방법, @ConfigurationProperties 어노테이션

결국, 설정의 구조가 복잡하거나 변경이 빈번한 경우에 `@Value` 어노테이션을 사용하면 유지보수가 어려울 수 있습니다. 이런 경우에는 설정이 객체 단위로 묶여서 바인딩하는 방법이 효과적일 수 있습니다. 

스프링에서는 `@ConfigurationProperties` 어노테이션을 사용하면 설정을 객체 단위로 바인딩할 수 있습니다. 즉, `application.properties` 또는 `application.yaml` 파일에 정의된 설정 구조가 그대로 코드 내부의 필드 구조로 표현되는 것입니다.

앞에서 사용했던 `application.yaml` 파일의 내용을 다시 한번 살펴보겠습니다.

```yaml
external:
  api:
    url: https://example.com
    timeout: 3000
    retry: 3
```

위의 설정을 객체 단위로 묶어서 바인딩하려면 `@ConfigurationProperties` 어노테이션으로 클래스를 선언하면 됩니다.

```java
@ConfigurationProperties(prefix = "external.api")
public class ExternalApiProperties {

    private String url;
    private int timeout;
    private int retry;

    // getter 
    // setter
}
```

**중요 포인트**

> prefix = "external.api"은 `application.yaml` 파일의 external.api 하위 설정을 바인딩하도록 요청하는 것을 의미합니다.

이렇게 하면 설정이 개별 값이 아닌 의미 있는 단위로 묶어 표현되기 때문에, 단위 기능 별 설정 구조를 직관적으로 파악하는데 도움이 됩니다.

## 설정도 결국 설계의 대상 

설정도 결국은 설계 대상이라고 합니다.
검증이 없다면 설정 오류는 숨은 장애 포인트가 될 수 있고,
바인딩 방식이 불명확하다면 기대와 다른 값이 주입되어 의도하지 않은 동작을 만들 수 있기 때문입니다.
따라서 `@ConfigurationProperties` 어노테이션을 사용하더라도,
설정에는 명확한 의도와 제약을 함께 표현하는 것이 중요합니다.
