회사에서 운영하고 있는 서비스를 들여다보면, 애플리케이션의 로그 출력이 충분히 통제되고 있다는 느낌은 들지 않았습니다. 특히, 전화번호나 이메일주소 같은 민감 정보가 그대로 출력되어 있는 경우도 종종 보였습니다.

로그 출력에 대한 명확한 사내 표준이 없는 상태에서 각 개발자가 자신의 스타일에 맞춰 로그를 남기다 보니 그런것 같습니다.작년에 ISMS 심사를 준비하면서도 이러한 문제들이 이슈가 되기도 했습니다. 로그 관리에 대한 고민이 필요했습니다.

단순히 “주의하자”로는 해결하기 어려운 문제라고 생각했습니다. 그래서 다음과 같은 질문을 던지게 되었습니다.

> 개발자가 신경 쓰지 않아도, 로그 레벨에서 민감 정보가 자동으로 마스킹되도록 할 수는 없을까?

## 로그 마스킹, 다시 처음부터

처음에는 욕심을 많이 냈습니다.

JSON 구조를 파싱하고, 특정 필드만 선택적으로 마스킹하는 방식을 시도했습니다. 어노테이션 기반 정책을 적용하고, ObjectMapper를 커스터마이징하는 방식까지 확장해보았습니다.

하지만, 구조가 점점 복잡해지면서 코드의 처리 흐름을 이해하기가 어려워졌습니다. JSON의 직렬화/역직렬화 과정이 추가되면서 성능 부담도 무시할 수 없었습니다.
실무에 바로 적용하기에는 부담이 있는 구조라는 생각이 들었습니다.

그래서 모든 시도를 잠시 내려놓고, 다시 질문했습니다.

> 정말 필요한 것은 무엇인가?

결국 로그는 문자열입니다. 출력 직전에 한 번만 가공하면 충분하지 않을까요?

JSON을 파싱하지 않아도, 객체 구조를 분석하지 않아도,
문자열에서 패턴을 찾아 바꾸는 것만으로도 문제를 상당 부분 해결할 수 있을 것이라 생각했습니다.

그래서 가장 단순한 방식으로 돌아가 보기로 했습니다.

## 로그 마스킹의 방식

“마스킹을 어디에서 적용해야 할까요?”

민감 정보가 로그에 남는다는 것은 결국 로그 출력 시점의 문제입니다.
그렇다면 선택지는 몇 가지로 나눌 수 있습니다.

* 애플리케이션 코드 레벨에서 직접 처리
* JSON 직렬화 과정에서 처리
* 로깅 프레임워크 레벨에서 처리

각 방식은 나름의 장/단점이 있습니다.

### 1. 애플리케이션 코드에서 직접 마스킹

로그를 남기기 전에 개발자가 직접 값을 가공하는 방식입니다.

```java
log.info("phone={}", mask(phoneNumber));
```

이 방식은 가장 단순해 보이지만, 실질적으로는 문제가 있습니다.
모든 개발자가 일관되게 적용해야 합니다.
빠뜨리는 순간 그대로 노출됩니다.
기존 코드 전체를 점검해야 합니다.

결국, 개발자의 주의에 의존하는 방식입니다. 현재 같이 일하고 있는 개발자들이 로그를 남기는 방식과 크게 다르지 않았습니다.

### 2. JSON 직렬화 과정에서 마스킹

Jackson 모듈을 확장하는 방식입니다. 민감정보에 해당되는 특정 필드에 어노테이션을 붙이면, 직렬화 시점에 ObjectMapper를 커스터마이징해서 자동으로 마스킹이 됩니다.

이 접근은 구조적으로 우아해 보였습니다. 하지만 실제로 구현해보니 문제가 보였습니다.

* JSON이 아닌 로그는 어떻게 할 것인가?
* 문자열 조합 로그는 어떻게 처리할 것인가?
* 직렬화/역직렬화 비용은 무시해도 되는가?

그리고 무엇보다 구조가 복잡했습니다.

### 3. 로깅 프레임워크 레벨에서 처리

Logback에서 PatternLayout을 확장하여 출력 문자열을 가공하는 방식입니다.

이 방식의 장점은 명확했습니다.

* 애플리케이션 코드 수정 불필요
* 모든 로그에 일괄 적용
* 출력 직전 1회 처리
* JSON 파싱 불필요 

로그는 최종적으로 문자열로 출력됩니다. JSON 객체도, DTO도, RequestBody도
모두 로그에 찍히는 순간 문자열이 됩니다. 그렇다면 출력 직전에 한 번만 가공하면 충분하지 않을까요?

문자열에서 특정 패턴을 찾아 바꾸는 것. 그것만으로도 상당 부분의 문제는 해결될 것 같았습니다. 이 방식이 가장 단순하면서도 실용적인 해결책이라고 판단했습니다.

그래서 이번 토이 프로젝트에서는 이 방식을 선택하게 되었습니다.

## 패키지 구조

```markdown
sanghoon.study.logging.mask
 ├─ LoggingPatternMaskApplication
 │
 ├─ api
 │  ├─ controller
 │  │  └─ PayloadController
 │  ├─ service
 │  │  ├─ request
 │  │  │  └─ PayloadRequest 
 │  │  ├─ response
 │  │  │  └─ PayloadResponse
 │  │  └─ PayloadService
 │  └─ APIResponse
 │
 ├─ core
 │  ├─ SensitiveStringSanitizer
 │  └─ DefaultSensitiveStringSanitizer
 │     └─ Rule
 │
 └─ logback
    ├─ RuleSpecParser
    └─ MaskingPatternLayout
```
* api : 테스트용 엔드포인트(API)
* core : 문자열 마스킹 순수 로직
* logback : Logback 연동 어댑터(출력 직전 가공)
