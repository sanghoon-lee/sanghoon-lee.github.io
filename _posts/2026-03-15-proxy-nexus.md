대부분의 개발자는 오픈소스 라이브러리를 사용하는 것에 대해 크게 고민하지 않습니다.
Gradle이나 Maven과 같은 빌드 도구를 사용하면 Maven Central과 같은 공개 저장소에 쉽게 접근할 수 있기 때문입니다.
이러한 저장소에는 다양한 오픈소스 라이브러리가 배포되어 있습니다.

Gradle을 사용하는 프로젝트에서는 다음과 같이 저장소를 설정하는 것이 일반적입니다.

```
repositories {
    mavenCentral()
}
```

이렇게 설정해 두면 빌드 과정에서 필요한 라이브러리가 자동으로 다운로드됩니다.
개발자가 특별히 신경쓰지 않아도 다양한 라이브러리를 바로 사용할 수 있습니다.

하지만 모든 개발 환경이 동일한 것은 아닙니다. 보안 정책이나 네트워크 정책에 따라 외부 인터넷 접근이 제한되는 네트워크 환경에서 개발하는 조직도 적지 않습니다. 
저 역시 이런 환경에서 개발을 하고 있습니다.

자연스럽게 다음과 같은 질문이 생길 수 있습니다.

> 개발자가 사용하는 PC나 CI 서버가 외부 인터넷에 직접 접근할 수 없는 폐쇄망 환경에서는
오픈소스 라이브러리를 어떻게 가져와서 사용할 수 있을까요?

외부 인터넷 접근이 제한되어 공개 저장소에 직접 접근할 수 없다면, 오픈소스 라이브러리를 사용하는 과정은 생각보다 복잡해질 수 있습니다.
라이브러리를 외부에서 다운로드한 뒤, 내부 네트워크로 반입하는 절차가 필요할 수도 있습니다. 하지만, 매우 번거롭고 비효율적입니다.

그래서 보통 이런 경우에는 **내부에 사설 라이브러리 저장소(Artifact Repository)**를 운영합니다.
대표적인 도구로는 `Nexus`나 `Artifactory`와 같은 저장소 관리 시스템이 있습니다.
이러한 저장소를 통해 외부 라이브러리를 내부에서 관리하고, 개발 환경에서 안정적으로 사용할 수 있습니다.

+----------------------+
|   Development Zone   |
|----------------------|
| Developer PC         |
| CI/CD Server         |
| Build Server         |
+----------+-----------+
           |
           | internal access only
           v
+----------------------+
|      Trust Zone      |
|----------------------|
| Nexus Repository     |
|  - proxy repo        |
|  - hosted repo       |
|  - group repo        |
+----------+-----------+
           |
           | outbound via proxy only
           v
+----------------------+
|         DMZ          |
|----------------------|
| Forward Proxy        |
| (Outbound Proxy)     |
+----------+-----------+
           |
           | controlled internet access
           v
+----------------------+
|       Internet       |
|----------------------|
| Maven Central        |
| npm registry         |
| PyPI                 |
| Docker Hub           |
+----------------------+
