2025년에는 대규모 정보유출 사고가 연이어 발생했습니다. 그 영향으로 기관에서 보안점검 요구사항이 높아지고 있습니다.

 물론, 저희 회사의 경우에는 보안팀과 인프라팀에서 필수적인 보안 장비들의 운영과 24시간 보안관제를 수행하고 있기는 합니다. 하지만, 개발팀 차원에서의 관심과 노력도 필요하다고 생각했습니다. 그래서 보안취약점 진단에 관심을 가지게 되었습니다. 그리고 Trivy라는 오픈소스 도구를 알게 되었습니다.

### 1. 목표

---

Trivy를 이용해서 인터넷 연결이 되지 않도록 네트워크가 분리된 폐쇄망을 이용해야 하는 개발용PC의 로컬 디스크에 위치한 소스코드에 대해서 보안취약점 검사를 해보는 것입니다. 

중요한 보안취약점이 많이 진단되어 보안성을 강화할 수 있는 계기가 되면 좋겠습니다. 

### 2. Trivy 다운로드 및 설치

---

개발용PC에서는 직접 인터넷에 연결할 수가 없습니다. 그래서 인터넷 연결이 가능한 별도의 PC에서 설치 파일을 다운로드 받고, 개발용PC로 옮겨야 했습니다. 

Trivy 설치 파일의 다운로드 링크는 다음과 같습니다. 운영체제에 맞는 설치 파일을 선택해서 다운로드 받으면 됩니다. 제가 사용하는 개발용PC의 운영체제는 윈도우라서 
Windows Intel용 설치 파일을 선택했습니다. 

> https://github.com/aquasecurity/trivy/releases/

설치는 매우 간단합니다. 다운로드 받은 파일의 압축을 풀고, 원하는 경로로 이동시키면 끝입니다. 참고로 제가 설치한 경로는 다음과 같습니다.
> c:\trivy_0.68.1_windows-64bit

조금 편리하게 사용하기 위해서 환경변수를 다음과 같이 추가했습니다.
```
TRIVY_HOME=c:\trivy_0.68.1_windows-64bit
PATH=%PATH%;%TRIVY_HOME%
```

trivy가 동작하는지 확인해보기 위해서 명령 프롬프트 창에서 trivy의 버전정보를 확인해봤습니다. 버전정보를 확인하는 명령은 다음과 같습니다.
> trivy -v

명령 프롬프트 창에서 현재 PC에 설치된 trivy의 버전정보를 아래와 같이 확인할 수 있었습니다.

```
Microsoft Windows [Version 10.0.26200.7171]
(c) Microsoft Corporation. All rights reserved.

C:\Users\sangh>trivy -v
Version: 0.68.1
```

### 3. Trivy DB 구성
---
Trivy는 소프트웨어 취약점(CVE) 정보와 잘못된 설정(Configuration) 정보가 저장되어 있는 Trivy DB를 참고해서 보안취약점을 진단합니다. Trivy 설치 파일에는 Trivy DB는 포함되어 있지 않습니다. 인터넷 연결이 가능한 환경에서는 검사를 실행하기 전에 자동으로 최신 버전의 Trivy DB를 가져오기 때문에 신경쓰지 않아도 됩니다. 하지만, 폐쇄망에서는 외부에서 다운로드 받은 Trivy DB를 수동으로 가져와야 합니다.

Trivy DB가 저장되는 폴더 구조는 다음과 같습니다.
```
[Trivy DB 폴더]
 ├─ db/
 │   ├─ metadata.json
 │   ├─ vulnerability.db
 ├─ java-db/
 └─ …

```

DB폴더 구조가 Trivy가 기대하는 것과 다르면 db를 찾지 못합니다.
