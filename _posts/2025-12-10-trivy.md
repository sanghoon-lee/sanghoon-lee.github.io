최근 대규모 정보유출 사고가 연이어 발생하는 것을 보면서 제가 담당하고 있는 서비스의 보안성을 강화하는데 관심을 기울여야 하겠다는 생각이 들었습니다. 사실 지금까지는 기능의 구현과 성능 최적화에만 집중하면서 보안에 대해서는 소홀했던 것이 사실입니다.

### 1. 목표

---

우선, 소스코드의 보안취약점을 먼저 진단해보고 싶었습니다. 

인터넷에서 검색해보니 사용 가능한 도구들이 많았습니다. 그 중에서 오픈소스 기반으로 기업에서도 무료로 사용할 수 있으면서, 사용법이 간단한 것으로 알려진 Trivy를 사용해기로 했습니다.

타겟 소스코드는 개발용 PC의 로컬 저장소에 있는데, 인터넷 연결이 되지 않도록 네트워크가 분리된 폐쇄망을 사용해야 하는 환경이었습니다.

### 2. Trivy 다운로드 및 설치

---

다행히 Trivy는 인터넷 연결이 되지 않는 환경에서도 실행이 가능했습니다. 그래서 인터넷 연결이 가능한 PC에서 설치 파일을 다운로드 받아서 개발용PC로 옮겨서 설치했습니다. 

[**Trivy 다운로드**](https://github.com/aquasecurity/trivy/releases) 사이트에서 운영체제에 맞는 설치 파일을 선택하고, 다운로드 받으면 됩니다. 제가 사용하는 개발용PC의 운영체제는 윈도우라서 
Windows Intel용 설치 파일을 다운로드 받았습니다. 

설치는 매우 간단합니다. 다운로드 받은 파일의 압축을 풀고, 원하는 경로로 이동시키면 끝입니다. 참고로 저는 압축을 풀고, 다음의 경로로 파일들을 이동시켰습니다.
> c:\trivy_0.68.1_windows-64bit

그리고 조금 편리하게 사용하기 위해서 환경변수를 다음과 같이 추가했습니다.
```
SET TRIVY_HOME=c:\trivy_0.68.1_windows-64bit

SET PATH=%PATH%;%TRIVY_HOME%
```

### 3. Trivy 실행 확인

Trivy가 정상적으로 실행하는지 확인해보기 위해서 명령 프롬프트 창을 열었습니다. 그리고 버전정보를 확인해봤습니다.
버전정보를 확인하는 명령은 다음과 같습니다.
> trivy -v

아래는 제가 사용하는 개발용PC에서 버전정보를 확인해본 결과입니다.

```
Microsoft Windows [Version 10.0.26200.7171]
(c) Microsoft Corporation. All rights reserved.

C:\Users\sangh>trivy -v
Version: 0.68.1
```

### 4. Trivy DB 구성

---

Trivy DB는 Trivy가 사용하는 보안취약점 정보 데이터베이스입니다.

앞에서도 이야기했지만, 개발PC는 인터넷에 직접 연결할 수 없는 폐쇄망을 사용하는 환경입니다. 그래서 조금 귀찮기는 하지만 Trivy DB를 수동으로 구성해줘야만 보안취약점을 진단할 수 있습니다. 참고로 인터넷 연결이 가능한 환경에서는 보안취약점 진단을 시작하면서 자동으로 최신 버전의 Trivy DB를 가져오기 때문에 신경쓰지 않아도 됩니다.

Trivy DB는 다음과 같은 구조를 가져야 합니다.
```
[Trivy DB 폴더] 예시)c:\trivy\trivy_db
     ├─ db/
     │   ├─ metadata.json
     │   ├─ vulnerability.db
     ├─ java-db/
     ├─ …
     └─ …
```
