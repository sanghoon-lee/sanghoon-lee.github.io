지난 포스팅에서 Vault HA를 구성하는 핵심 개념과 Leader Election, 데이터 복제(Data Replication), 그리고 Failover가 어떻게 이루어지는지 살펴봤습니다.

개념은 이해할 수 있었습니다. 하지만 실제 운영 환경에서도 안정적으로 동작할지에 대해서는 확신을 가질 수 없었습니다. 

그래서 직접 Vault HA 클러스터를 구축하면서 하나씩 확인해보고 싶었습니다.

---

## 1. 실습 환경

Vault HA에서 사용하는 Raft 알고리즘은 과반수(Quorum)를 기반으로 Leader를 선출합니다. 따라서 일반적으로 홀수 개의 노드로 클러스터를 구성하는 것이 권장됩니다. 

이번 실습에서는 가장 단순한 형태의 HA 클러스터를 구성하기 위해 3개의 Vault 노드를 사용했습니다.

실습 환경은 다음과 같습니다.

| 구성 요소    | 내용                        |
| -------- | ------------------------- |
| OS     | Ubuntu 24.04 LTS          |
| Docker   | Docker Engine 29.3.0           |
| Vault    | HashiCorp Vault 1.21.4           |
| Storage  | Integrated Storage (Raft) |
| Network    | Docker Bridge Network     |

---

### 1.1. Docker 네트워크 생성

클러스터를 구성할 각 노드는 Docker 컨테이너로 생성했습니다. 실제 운영 환경에서는 일반적으로 실제 물리 서버나 가상머신을 사용해 노드를 생성합니다. 하지만 실습을 목적으로 이러한 환경을 준비하기에는 서버 구성이나 네트워크 설정 등 준비 과정이 다소 복잡해질 수 있습니다.

Docker 컨테이너로 실행하더라도 각 Vault 노드는 서로 통신할 수 있어야 합니다. 그래야 Raft 프로토콜을 이용한 Leader Election과 데이터 복제가 정상적으로 이루어질 수 있습니다.

그래서 먼저 컨테이너들이 함께 사용할 Docker 네트워크를 생성했습니다.

```bash
$ docker network create vault-network
```

네트워크가 정상적으로 생성되었는지도 확인했습니다.

```bash
$ docker network ls
```

아래와 같이 실행 결과에서 `vault-network`가 조회되는 것을 확인할 수 있었습니다.

```nohighlight
NETWORK ID     NAME            DRIVER    SCOPE
9094e2030af0   vault-network   bridge    local
```

이후 `vault-1`, `vault-2`, `vault-3`이라는 이름의 컨테이너를 생성하고, 모두 `vault-network`에 연결하여 하나의 Vault HA 클러스터를 구성했습니다.

---

### 1.2. Vault 실행 모드의 선택

Vault는 다음과 같이 두 가지 실행 모드를 제공합니다.

* 개발 모드(Development Mode) : `vault server -dev` 명령으로 실행하며 Init과 Unseal을 자동으로 수행하여 기능을 빠르게 실습할 수 있습니다.
* 서버 모드(Server Mode) : `vault server -config` 명령으로 실행하며 설정 파일을 이용해 Vault를 실행하는 방식으로 Storage와 Listener 등 운영에 필요한 설정을 직접 지정할 수 있습니다.

Vault에서 제공하는 대부분의 기능을 실습하는 것은 개발 모드로 실행해도 충분합니다. 

하지만 Vault HA 클러스터를 구축하려면 개발 모드가 아닌 서버 모드로 실행해야 합니다. Raft를 이용한 Leader Election과 데이터 복제 기능을 사용하려면 각 노드의 Storage, API 주소, Cluster 주소 등을 직접 설정해야 하기 때문입니다. 

---

### 1.3. Vault 설정 파일의 작성

Vault의 서버 모드는 HCL(HashiCorp Configuration Language) 형식의 설정 파일을 이용해 실행합니다.

먼저 `vault-1`에서 사용할 `vault-1.hcl` 파일을 아래와 같이 작성했습니다.

```hcl
ui = true
disable_mlock = true

listener "tcp" {
  address         = "0.0.0.0:8200"
  cluster_address = "0.0.0.0:8201"
  tls_disable     = true
}

storage "raft" {
  path    = "/vault/data"
  node_id = "vault-1"
}

api_addr     = "http://vault-1:8200"
cluster_addr = "http://vault-1:8201"
```

각 설정의 의미는 다음과 같습니다.

| 설정               | 설명                                       |
| ---------------- | ---------------------------------------- |
| `ui`             | Vault Web UI를 활성화합니다.                    |
| `disable_mlock`  | Docker 환경에서 메모리 잠금 기능을 비활성화합니다.          |
| `listener`       | Vault가 클라이언트 요청과 클러스터 통신을 수신할 주소를 설정합니다. |
| `storage "raft"` | Raft 기반의 Integrated Storage를 사용하도록 설정합니다.       |
| `path`           | Raft 데이터가 저장될 디렉토리입니다.                   |
| `node_id`        | 클러스터에서 각 노드를 구분하기 위한 고유 ID입니다.           |
| `api_addr`       | 클라이언트와 다른 노드가 접근하는 API 주소입니다.            |
| `cluster_addr`   | Vault 노드 간 통신에 사용하는 주소입니다.               |

이어서 `vault-2`와 `vault-3`에서 사용할 `vault-2.hcl`과 `vault-3.hcl` 파일도 작성했습니다.

대부분의 설정은 `vault-1.hcl`과 동일하지만, 아래의 값들은 컨테이너에 맞게 변경했습니다.

* `node_id`
* `api_addr`
* `cluster_addr` 

**`vault-2.hcl`에서 변경되는 부분**

```hcl
storage "raft" {
  path    = "/vault/data"
  node_id = "vault-2"
}

api_addr     = "http://vault-2:8200"
cluster_addr = "http://vault-2:8201"
```

**`vault-3.hcl`에서 변경되는 부분**

```hcl
storage "raft" {
  path    = "/vault/data"
  node_id = "vault-3"
}

api_addr     = "http://vault-3:8200"
cluster_addr = "http://vault-3:8201"
```

이번 실습에서는 설정 파일을 모두 계정의 홈 디렉터리(/home/sanghoon)에 작성했습니다.

### 1.4. 컨테이너 실행

Vault는 Raft 데이터를 디스크에 저장하므로 각 노드마다 별도의 데이터 저장 디렉토리가 필요합니다.

그래서 각 노드에서 사용할 데이터 저장 디렉토리도 생성했습니다. 

```bash
$ mkdir -p vault-1 vault-2 vault-3
```

각 노드에서 사용할 설정 파일과 데이터 저장 디렉토리를 모두 동일한 위치에 생성했습니다.

```md
/home/sanghoon
 ├── vault-1.hcl
 ├── vault-2.hcl
 ├── vault-3.hcl
 ├── vault-1/
 ├── vault-2/
 └── vault-3/
```

Vault 노드(`vault-1`, `vault-2`, `vault-3`)를 컨테이너로 실행할 때는 앞에서 생성한 `vault-network`에 연결하고, 각 노드에 맞는 설정 파일과 데이터 저장 디렉토리를 마운트해야 합니다. 또한 메모리 잠금(mlock) 기능을 사용할 수 있도록 `IPC_LOCK` Capability도 함께 추가했습니다.

먼저 `vault-1` 컨테이너를 아래와 같이 실행했습니다.

```bash
$ docker run -d \
  --name vault-1 \
  --network vault-network \
  --cap-add=IPC_LOCK \
  -p 8200:8200 \
  -v /home/sanghoon/vault-1.hcl:/vault/config/vault.hcl \
  -v /home/sanghoon/vault-1:/vault/data \
  hashicorp/vault \
  vault server -config=/vault/config/vault.hcl
```

> **참고**
>
> 각 Vault 컨테이너는 내부적으로 모두 8200 포트를 사용합니다. 하지만 하나의 호스트에서 여러 컨테이너를 실행하기 때문에 호스트 포트는 서로 다르게 매핑해야 합니다.
>
> 따라서 `vault-2`와 `vault-3`는 각각 `8202:8200`, `8204:8200`과 같이 실행했습니다.
>
> 반면 Vault 노드 간 통신은 Docker 네트워크 내부에서 이루어지므로 설정 파일의 `api_addr`와 `cluster_addr`는 모두 컨테이너 이름과 내부 포트(8200, 8201)를 그대로 사용하면 됩니다.

그리고 나머지 컨테이너들도 아래와 같이 실행했습니다.

**vault-2 컨테이너**
```bash
$ docker run -d \
  --name vault-2 \
  --network vault-network \
  --cap-add=IPC_LOCK \
  -p 8202:8200 \
  -v /home/sanghoon/vault-2.hcl:/vault/config/vault.hcl \
  -v /home/sanghoon/vault-2:/vault/data \
  hashicorp/vault \
  vault server -config=/vault/config/vault.hcl
```

**vault-3 컨테이너**
```bash
$ docker run -d \
  --name vault-3 \
  --network vault-network \
  --cap-add=IPC_LOCK \

  -v /home/sanghoon/vault-3:/vault/data \
  hashicorp/vault \
  vault server -config=/vault/config/vault.hcl
```

그리고 모든 컨테이너가 정상적으로 실행되었는지 확인했습니다.

```bash
$ docker ps
```

`vault-1`, `vault-2`, `vault-3`가 모두 실행 중(Up) 상태라는 것을 확인할 수 있었습니다.

## 2. Vault 초기화 및 Unseal

하지만, 아직은 컨테이너만 실행된 상태이며 Vault를 사용할 수 있는 상태는 아닙니다. Vault는 보안을 위해 처음 실행되면 Sealed 상태로 시작하기 때문입니다. Sealed 상태에서는 Vault에서 제공하는 보안 기능들을 사용할 수 없습니다.

그래서 클러스터를 초기화(Init)해서 각 노드를 Unseal하는데 필요한 Unseal Key를 생성해야 합니다.

---

### 2.1. 초기화

클러스터가 초기화(Init)되면 Unseal Key가 생성됩니다. 중요한 점은 `vault-1`, `vault-2`, `vault-3`을 각각 초기화하는 것이 아니라는 것입니다. 클러스터를 구성하는 노드 중 하나에서만 수행하면 됩니다. 이후 생성된 Unseal Key를 이용해 나머지 노드도 Unseal할 수 있습니다. 

이번 실습에서는 `vault-1` 노드에서 초기화를 수행했습니다. Vault CLI를 사용하기 위해 먼저 `vault-1` 컨테이너 내부에 접속했습니다.

```bash
$ docker exec -it vault-1 sh
```

컨테이너 내부에서 Vault CLI를 사용하기 전, 접속할 Vault 서버 주소를 지정해야 합니다. 이를 위해 `VAULT_ADDR` 환경변수를 아래와 같이 설정했습니다.

```bash
/ # export VAULT_ADDR=http://127.0.0.1:8200
```

그리고 아래 명령으로 Vault를 초기화할 수 있었습니다.

```bash
/ # vault operator init
```

초기화가 완료되면 아래와 같이 Unseal Key와 Initial Root Token이 출력됩니다.  

```nohighlight
Unseal Key 1: 1QrU2aDoWFOcX0PeNwWSGaJcF5rf0vYvq8GJxhTwNhuR
Unseal Key 2: +BWTXfwt2wjPjnZNV70whFYWB5bKWMukkKs6QEJQyLj9
Unseal Key 3: 7EODeGOJySb23Eimo2GoFDTKCxXyppHsv6MYDZz428iA
Unseal Key 4: M7cOWSdp7I0II7NpKigZFSo3GrRCDy9VZsuo7ZWHYHuP
Unseal Key 5: k6iskFycK1AywH7dsu5U/HEmZfcXjaEXL/Va3DcREst2

Initial Root Token: hvs.ZBevOGkFLXhvBmhfAGva6Yy7
```

* Unseal Key : Vault를 Unseal하는 데 사용됩니다.
* Initial Root Token : 최초 관리자 권한으로 로그인할 때 사용됩니다.

Vault는 기본적으로 5개의 Unseal Key를 생성하며, 이 중 3개 이상의 키를 입력해야 Unseal이 완료됩니다(Threshold = 3).

Unseal Key와 Initial Root Token은 반드시 안전한 곳에 따로 보관해야 합니다. 외부에 절대 노출하면 안됩니다. 지금은 실습이기 때문에 실제 초기화를 통해 생성된 값을 첨부했습니다. 

---

### 2.2. vault-1 Unseal

먼저 `vault-1`부터 Unseal했습니다. 컨테이너 내부에 접속한 상태에서 아래 명령으로 Unseal할 수 있었습니다.

```bash
/ # vault operator unseal
```

명령을 실행하고, Unseal Key 하나를 입력합니다. Unseal이 성공하면 아래와 같은 결과가 출력됩니다.

```nohighlight
Key                     Value
---                     -----
Seal Type               shamir
Initialized             true
Sealed                  true
Total Shares            5
Threshold               3
Unseal Progress         1/3
Unseal Nonce            49b1dd93-c293-8372-028c-decf6dd16ec0
Version                 1.21.4
Build Date              2026-03-04T17:40:05Z
Storage Type            raft
Removed From Cluster    false
HA Enabled              true
```

첫 번째 Unseal Key를 입력한 상태이므로 Sealed는 아직 true이며, Unseal Progress가 1/3으로 표시됩니다.

같은 명령을 다시 실행하여 서로 다른 Unseal Key를 입력하는 과정을 반복합니다. 기본 설정에서는 총 3개의 서로 다른 Unseal Key를 입력하면 Vault가 Unseal 상태로 전환됩니다.

### 2.3. vault-2 Raft Join과 Unseal 

`vault-1`을 초기화하면 앞에서 설정한 storage "raft" 구성을 기반으로 vault-1만 포함된 Raft 클러스터가 생성됩니다. 아직은 하나의 노드만 포함된 클러스터이지만, 이후 다른 노드가 순차적으로 참여하게 되면 하나의 HA 클러스터가 완성됩니다.

따라서 `vault-2`와 `vault-3`는 먼저 `vault-1`이 생성한 Raft 클러스터에 참여해야 합니다. 아직 클러스터에 아직 클러스터에 참여하지 않은 상태에서는 초기화 정보를 아직 전달받지 못했기 때문에 vault operator unseal 명령을 실행하면 다음과 같은 오류가 발생합니다.

> Vault is not initialized

이번에는 `vault-2` 컨테이너 내부에 접속했습니다.

```bash
$ docker exec -it vault-2 sh
```

그리고 `vault-1`과 동일하게 Vault CLI가 접속할 서버 주소를 지정하기 위해 `VAULT_ADDR` 환경변수를 설정했습니다.  

```bash
/ # export VAULT_ADDR=http://127.0.0.1:8200
```

`vault-2`를 Raft 클러스터에 참여시키기 위해 아래 명령을 실행했습니다.

```bash
/ # vault operator raft join http://vault-1:8200
```

명령이 정상적으로 실행되면 아래와 같은 응답이 출력됩니다.

```nohighlight
Key       Value
---       -----
Joined    true
```

> 참고: `VAULT_ADDR`는 명령을 실행할 현재 컨테이너(vault-2)의 주소를 가리킵니다. 반면 raft join 명령의 인수인 http://vault-1:8200은 참여할 대상 클러스터의 Leader 주소('vault-1`)를 의미합니다.

Raft 클러스터에 참여가 완료되면 `vault-1`으로부터 초기화 정보가 공유됩니다. 그래서 `vault-1`과 동일한 방식으로 Unseal 상태로 전환할 수 있었습니다. 

---

### 2.4. vault-3 Raft Join과 Unseal 

`vault-3` 역시 `vault-2`와 동일한 절차로 Raft 클러스터에 참여시키고, Unseal 상태로 전환할 수 있었습니다.

```bash
/# vault operator raft list-peers
```

```nohighlight
Node       Address             State      Voter
```
