지금까지 Vault의 개념을 살펴보고, CLI를 사용해서 Transit Engine의 암·복호화 기능을 직접 실행해보았습니다.

이제 Vault와 연동하여 암·복호화를 수행하는 코드를 작성해보겠습니다.

Vault의 동작 방식을 설명하는데 초점을 맞춰 간단한 Java 콘솔 프로그램으로 구현했습니다.

---

## 1. 전체 코드

Vault의 Transit Engine을 호출하여 문자열을 암호화하고, 다시 복호화까지 수행하는 간단한 예제 코드입니다.

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;
import java.util.Base64;

public class VaultConsoleExample {
    public static void main(String[] args) {
        String vaultAddr = "http://192.168.50.69:8200"; // Vault 주소는 환경에 맞게 변경
        String token = "root";

        try {
            HttpClient client = HttpClient.newHttpClient();

            // =========================
            // 1. 암호화
            // =========================

            String plaintext = "hello,vault";
            String encoded = Base64.getEncoder().encodeToString(plaintext.getBytes());

            String encryptJson = "{ \"plaintext\": \"" + encoded + "\" }";

            HttpRequest encryptRequest = HttpRequest.newBuilder()
                    .uri(URI.create(vaultAddr + "/v1/transit/encrypt/test-key"))
                    .header("X-Vault-Token", token)
                    .header("Content-Type", "application/json")
                    .POST(HttpRequest.BodyPublishers.ofString(encryptJson))
                    .build();

            HttpResponse<String> encryptResponse =
                    client.send(encryptRequest, HttpResponse.BodyHandlers.ofString());

            if (encryptResponse.statusCode() != 200) {
                System.out.println("암호화 실패");
                System.out.println(encryptResponse.body());
                return;
            }

            System.out.println("암호화 성공");
            System.out.println(encryptResponse.body());

            // 간단하게 ciphertext 추출 (문자열 파싱)
            String ciphertext = extractValue(encryptResponse.body(), "ciphertext");

            // =========================
            // 2. 복호화
            // =========================

            String decryptJson = "{ \"ciphertext\": \"" + ciphertext + "\" }";

            HttpRequest decryptRequest = HttpRequest.newBuilder()
                    .uri(URI.create(vaultAddr + "/v1/transit/decrypt/test-key"))
                    .header("X-Vault-Token", token)
                    .header("Content-Type", "application/json")
                    .POST(HttpRequest.BodyPublishers.ofString(decryptJson))
                    .build();

            HttpResponse<String> decryptResponse =
                    client.send(decryptRequest, HttpResponse.BodyHandlers.ofString());

            if (decryptResponse.statusCode() != 200) {
                System.out.println("복호화 실패");
                System.out.println(decryptResponse.body());
                return;
            }

            System.out.println("복호화 성공");
            System.out.println(decryptResponse.body());

            // Base64 plaintext 추출
            String decodedBase64 = extractValue(decryptResponse.body(), "plaintext");

            // Base64 → 원문 문자열
            String result = new String(Base64.getDecoder().decode(decodedBase64), StandardCharsets.UTF_8);

            System.out.println("최종 복호화 결과: " + result);

        } catch (Exception e) {
            System.out.println("Vault 호출 중 오류 발생");
            e.printStackTrace();
        }
    }

    // 간단한 JSON 값 추출 (예제용)
    // 실무에서는 JSON 파싱 라이브러리(Jackson 등)를 사용하는 것이 좋습니다.
    // 특히 응답 구조가 변경될 수 있기 때문에, 문자열 파싱 방식은 유지보수에 취약할 수 있습니다.
    private static String extractValue(String json, String key) {
        String pattern = "\"" + key + "\":\"";
        int start = json.indexOf(pattern) + pattern.length();
        int end = json.indexOf("\"", start);
        return json.substring(start, end);
    }
}
```

## 2. 코드 설명

코드는 다음과 같은 흐름으로 구성되어 있습니다.

---

### 2.1. 인코딩/디코딩

**암호화: 평문을 Base64로 인코딩**
```java
String encoded = Base64.getEncoder().encodeToString(plaintext.getBytes());
```

Vault의 Transit Engine은 입력값을 Base64 형태로 받기 때문에, 암호화를 요청하기 전에 반드시 인코딩 과정이 필요합니다.

> Vault는 내부적으로 바이너리 데이터를 처리하기 때문에, 문자열을 그대로 전달하면 오류가 발생할 수 있습니다. 

**복호화: 복호화된 결과를 Base64로 디코딩**
```java
String result = new String(Base64.getDecoder().decode(decodedBase64), StandardCharsets.UTF_8);
```

복호화 결과는 Base64 형태로 반환되기 때문에, 애플리케이션에서는 디코딩 과정을 통해 원본 문자열을 복원해야 합니다.


---

### 2.2. Vault API 호출

Vault는 별도의 전용 프로토콜을 사용하는 것이 아니라, HTTP 기반의 REST API로 동작합니다.

따라서 애플리케이션에서는 다음과 같은 방식으로 Vault를 사용할 수 있습니다.

```
애플리케이션 → HTTP 요청 → Vault → 결과 반환
```

즉, 일반적인 REST 호출만으로도 Vault를 쉽게 연동할 수 있습니다.

**암호화 요청 생성**
```java
HttpRequest encryptRequest = HttpRequest.newBuilder()
        .uri(URI.create(vaultAddr + "/v1/transit/encrypt/test-key"))
        .header("X-Vault-Token", token)
        .header("Content-Type", "application/json")
        .POST(HttpRequest.BodyPublishers.ofString(encryptJson))
        .build();
```

* /v1/transit/encrypt/test-key → 암호화 API 경로
* X-Vault-Token → 인증 토큰


**복호화 요청 생성**
```java
HttpRequest decryptRequest = HttpRequest.newBuilder()
        .uri(URI.create(vaultAddr + "/v1/transit/decrypt/test-key"))
        .header("X-Vault-Token", token)
        .header("Content-Type", "application/json")
        .POST(HttpRequest.BodyPublishers.ofString(decryptJson))
        .build();
```

* /v1/transit/decrypt/test-key → 복호화 API 경로
* X-Vault-Token → 인증 토큰

---

### 2.3. 응답 결과 확인

**암호화**
```java
System.out.println(encryptResponse.body());
```

Vault는 다음과 같은 형태로 암호화 결과를 반환합니다. data.ciphertext 값이 실제 암호화된 결과이며, Vault에서 관리하는 자체 포맷(vault:v1:...)으로 반환됩니다.

```json
{
  "data": {
    "ciphertext": "vault:v1:xxxxxxxx",
    "key_version": 1
  }
}
```

**복호화**
```java
System.out.println(decryptResponse.body());
```

Vault는 다음과 같은 형태로 복호화 결과를 반환합니다. data.plaintext 값이 실제 복호화된 결과(Base64로 인코딩된 값)입니다. 

```json
{
  "data": {
    "plaintext": "aGVsbG8sd29ybGQ="
  }
}
```

## 3. 마무리

Vault는 암호화 키를 애플리케이션 외부에서 관리하고, API를 통해 암·복호화 기능을 제공한다는 점에서 기존 KMS와 유사한 구조를 가지고 있습니다.

이러한 구조에서는 애플리케이션에서 직접 키를 관리하지 않아도 되기 때문에, 키 유출 위험을 줄이고 보안성을 높일 수 있습니다.

Vault는 단순한 Secret 저장소를 넘어, 암호화를 외부 서비스 형태로 제공하는 플랫폼입니다.

KMS에서 키만 보관하고, 실제 암호화 연산은 애플리케이션에서 수행하는 구조에서 Vault를 도입하면 암호화 연산까지도 외부 시스템으로 분리하는 효과가 추가됩니다.

물론 Vault는 소프트웨어 기반 솔루션이기 때문에 HSM(Hardware Security Module)과 동일한 수준의 보안을 제공한다고 보기는 어렵습니다.

그럼에도 불구하고, 암호화 키와 연산을 모두 외부에서 처리한다는 점에서 기존보다 한 단계 강화된 보안 구조를 구성할 수 있습니다.

👉 **Vault는 KMS를 단순히 대체하는 것을 넘어, 보안 아키텍처 자체를 변화시키는 요소가 될 수 있습니다.**

실습을 통해 기본적인 동작을 확인한 결과, 기술적인 측면에서는 KMS를 대체할 수 있는 가능성이 충분하다고 판단할 수 있습니다.

다만 운영 복잡성, 보안 요구사항, 인프라 구성 등을 함께 고려해야 하기 때문에, 실제 도입 여부는 환경에 맞는 추가적인 검토가 필요합니다.
